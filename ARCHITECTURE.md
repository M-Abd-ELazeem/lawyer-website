# Architecture — Feature-Sliced Design

This project follows [Feature-Sliced Design](https://feature-sliced.design/).

## Layers

Highest to lowest. **A layer may only import from layers strictly below it.**

| Layer       | Holds                                                      |
| ----------- | ---------------------------------------------------------- |
| `app/`      | Next.js routing, root layout, providers, global styles      |
| `views/`    | One composition per route ("pages" in FSD terms)            |
| `widgets/`  | Large self-contained page sections                          |
| `features/` | Things a user *does* (submit a consultation request)        |
| `entities/` | Business entities (the office, a service, an article)       |
| `shared/`   | Reusable and business-agnostic: UI kit, icons, lib, config  |

### Why `views/` and not `pages/`

FSD names this layer `pages`. That name is unusable here: a top-level
`pages/` directory **is the Next.js Pages Router**, and its files would be
picked up as routes. `views/` is the standard workaround for FSD on Next.

### `app/` is routing only

Route files stay thin and delegate to `views/`:

```tsx
// app/articles/page.tsx
import { ArticlesPage } from "@/views/articles";
export default ArticlesPage;
```

Next requires a **default** export from `page.tsx`, `layout.tsx`, `route.ts`
and `error.tsx`. Everywhere else uses named exports.

## Slices and segments

Each layer (except `shared`, which has segments only) divides into slices:

```
widgets/contact-section/
  ui/        components
  model/     types, state
  lib/       slice-local helpers
  api/       data access
  index.ts   public API
```

**Import a slice only through its `index.ts`.** Deep imports into another
slice's internals are what makes a structure impossible to refactor later.

## Rules are enforced, not just documented

`eslint.config.mjs` applies `no-restricted-imports` per layer. All three
violations fail `npm run lint`:

- **Upward import** — `entities/` importing from `@/widgets/*`
- **Cross-slice import** — `entities/office` importing `@/entities/service`
- **Deep import** — anything importing `@/widgets/hero/ui/Hero` instead of
  `@/widgets/hero`

If two slices in one layer need the same code, move that code **down** a
layer rather than importing sideways.

> Both rules must live in a **single** `no-restricted-imports` entry per
> layer. A later flat-config block replaces a rule's options rather than
> merging them, so splitting them into two configs silently disables the
> first one.

## Adding an API integration

Every getter lives in an entity's `api/` segment and falls back to seed
data while `API_BASE_URL` is unset:

```ts
// entities/service/api/get-services.ts
export async function getServices(): Promise<Service[]> {
  if (!hasApi) return seedServices;
  const dto = await apiGet<ServiceDto[]>("/services", { revalidate: 3600, tags: ["services"] });
  return dto.map(toService);   // DTO -> domain model
}
```

Components call the getter and never touch seed data, so connecting a CMS
is a change to that one file. Note `fetch` is **not** cached by default in
Next 16 — `shared/api/client.ts` takes `revalidate`/`tags` per call.

Content stores icons as **string keys** (`icon: "building"`), resolved
through `shared/ui/icons/registry.ts`. That is what lets a JSON API supply
an icon; JSX embedded in a data array could never come over the wire.

## Where does a new file go?

- Business-agnostic and reusable anywhere → `shared/`
- Describes a *thing* in the domain → `entities/<thing>/`
- Describes something a user *does* → `features/<action>/`
- A big composed section of a page → `widgets/<section>/`
- Assembles widgets into one route → `views/<route>/`

## Next.js specifics worth knowing

- **`params` is a Promise.** Synchronous access was removed in Next 16.
  `const { slug } = await params`.
- **Route types** (`PageProps<"/articles/[slug]">`) are generated by
  `next dev` / `next build` / `next typegen`. Run `npx next typegen` after
  adding a dynamic route or the type will not resolve.
- **`error.tsx` takes `unstable_retry`**, which replaced `reset` as the
  recovery prop in 16.2.
- **Streamed responses cannot return 404.** Once a Suspense boundary (such
  as a `loading.tsx`) has rendered, headers are sent and `notFound()` can
  only mark the page `noindex`. The articles listing therefore lives in an
  `(list)` route group so its `loading.tsx` does not wrap `[slug]`, which
  lets unknown slugs return a real 404. Keep that in mind before adding a
  `loading.tsx` to a segment that has dynamic children.

## Known remaining work

`app/globals.css` still defines ~15 utility classes by hand (`.text-gold`,
`.bg-dark-card`, …) on a plain `:root` block. Tailwind v4 could generate
these from an `@theme` block, along with every variant (`hover:text-gold`),
for free. Two snags to handle when doing it:

- `.bg-dark-section` resolves to `var(--dark)` while `.bg-dark-secondary`
  resolves to `var(--dark-section)`. The names are inverted. This is now
  contained behind `Section`'s `tone` prop.
- `.border-gold` is currently the shorthand `border: 1px solid`, whereas a
  generated `border-gold` would set colour only. `widgets/about` relies on
  the shorthand and would need `border border-gold`.
